## 1. 版本目標

**一句話**：把「算術遊戲」升級為「經營遊戲」，服務三類用戶——**新手（學）、泛經營玩家（爽）、達人（走向真實合作）**。

**遊戲定位**：獲客漏斗 + 教育工具 + 合作篩選器。遊戲內留存 / 付費不是目的；目的是讓人進來、玩懂、願意真實合作。

**北極星**：**達人進來 → 玩懂 → 留資 → 真實合作**。當遊戲內指標與漏斗指標衝突時，以漏斗為準。

**四個可衡量的目標**（按優先級）：1. 爽感先行（新手 3 輪內玩爽、達人第 1 輪就有「我能帶貨」的感覺；上難度的改動緩行）；2. 玩懂有路徑（達人看故事、新手看邏輯卡、泛經營玩家看數字和戰報；決策→反饋延遲縮短）；3. 合作有出口（認證體系 + 認證卡留資 + 行為數據評估）；4. 不再教錯（真實性修復只修教錯的地方，不疊加難度）。

**非目標**（v2 再說）：不加硬門禁、不做雙模式（已廢止）、不做完整經濟系統（賬期 / 倉儲 / 破產事件 / 大賣季節點）、不開雙身份開場（漏斗入口零摩擦）。

## 2. 設計原則（本版本憲法，評審時回看）

1. **牽引代替管制**：初版不加限制。別做「牆」，做「燈」——門全開，燈光打在推薦的路上。
2. **三受眾分層**：新手（學）+ 泛經營玩家（爽）+ 達人（走向真實合作）。遊戲為表，模擬器為裏，漏斗為底；教育分層——達人看故事、新手看邏輯卡、泛玩家看數字戰報；透明但不強制（「？」下鑽）。
3. **先爽後學（獲客邏輯）**：前 3 輪遊戲向（爽、快），之後引入教學向（歸因頁講「為什麼」）。難度邏輯反轉：作為獲客工具，上難度的改動緩行，優先保證「爽 + 我能行」。
4. **交集先行**：三受眾共同受益的先做（真實性修復 > 純爽點 > 純教學點）；達人專屬（認證 / 合作引導）單獨排期，不拖累主線。
5. **北極星優先**：評審時遇到「遊戲內指標 vs 漏斗指標」分歧，一律以漏斗為準。
6. **漏斗入口零摩擦**：不開雙身份開場；用成長線代替身份分支——單主角「出海合夥人」，達人能力 / 運營能力都做成可成長技能樹，玩家按短板自選補齊，行為數據自動分流評估。
7. **下一版總原則（REQ-053 延續）**：一步 ≤3 個決策、一屏一主行動、數字可算、運氣 < 技術、學在事後、失敗不螺旋、單模式 2.5D。

**REQ-048 財報 · 三大表** `M` ❌（落地載體：W6）
- 背景：v2 引擎已有現金 / 庫存 / 應收 / 應付 / 橋貸 / 14 天回款全套資金數據，但只散落在戰報明細行裏。三大表以**呈現層為主，不新增數值系統**。
- 入口：結算區新增「財報」頁籤（與戰報 / 評估並列）；每輪結算自動生成本期財報，歷史輪次可翻看。
- **利潤表**：收入 → 退款 → 各項成本（貨品 / 退貨處理 / 上架 / 運費 / 平台費 / 佣金 / 推廣 / 關稅 / 進口稅 / 收款費 / 換匯 / 頭程 / 倉儲 / 利息）→ 毛利 → 淨利潤；復用戰報瀑布數據並補匯總行，口徑與戰報嚴格一致。
- **資產負債表**（期末時點）：資產 = 現金 + 存貨（餘貨 × 單位成本）+ 應收賬款（待到賬）；負債 = 應付採購款 + 橋貸未還本金；淨資產 = 資產 − 負債；每行帶與上輪對比的變化箭頭。
- **現金流量表**：期初現金 + 本輪到賬回款（含上輪應收在本輪到賬部分）− 本輪實際付現（採購 / 運費 / 稅費 / 推廣 / 利息等）= 期末現金。
- **勾稽自檢（硬驗收）**：① 資產 = 負債 + 淨資產；② 本輪淨資產變動 = 本輪淨利潤；③ 期末現金三處一致（現金流量表結果 = 資產負債表現金行 = 實際現金）。任一對不上即 bug，不許上線。
- 教學化：科目用標準名 + 小字人話註釋（如應收賬款旁注「貨賣了、錢還沒到賬的部分」）；每表底部一句話解讀；**重點講清「利潤 ≠ 現金」**：差額來源逐項點名（未到賬 $X + 壓在貨上 $Y）。
- 預警：期末現金 < 近期應付時，資產負債表紅字提示「現金可能接不上應付」。
- 兼容：v1.1 輪次無賬期數據，只出利潤表；v2 輪次出全三表。與 REQ-046 聯動：完整版評估報告引用淨資產變化作成績錨點。
- **更名過渡（定版）**：三大表上線之前，W6 對外稱「結算廳」；三大表上線驗收通過後，恢復「財報結算廳」原名。不得在無三大表的情況下繼續叫財報結算廳。
- 驗收：任意 v2 輪次結算後三表生成且勾稽三條全過；玩家能從財報一句話答出「本輪賺了多少、現金剩多少、錢壓在哪」。

  5. **回歸**：W3 優化按鈕補回（$300 +5 分、上限 95，旁寫預計回報，按上輪到訪算）；舊面板文案全量掃描（首進一次進入費、按成本退回扣 5%、續留免費、目標按通過次數漲），實現方逐處列出改動清單。
- 驗收：見 §4（P2 + 回歸測試 + 截圖留證）。

### 3.3 新增需求（P1 驗收後新立項，編號順延）

**REQ-054 頭程到貨率分層（P1 驗收硬傷修復）** `S` ❌新增
- 背景（P1 附錄 B 自認）：頭程三檔到貨率都被 75% 下限抬平——空運共 9 天按公式只有 70%，也被抬到 75%，空運多花錢卻不多到貨，頭程選擇失去意義。實現方當時未擅自改數值，留待產品側拍板；本條即為拍板。
- 定版（不許再議）：到貨率下限只保最便宜檔；三檔展示值必須不同——**海運 75%（下限不變）、海空聯運 85%、空運 95%**，上限 100%。運費、時效、收費時點（履約步、發貨時收）一律不變；舊存檔已付頭程不重複收的規則不變。
- 展示：W5 頭程航線終端三檔並排寫明天數 / 單件運費 / 本輪到貨率；三檔到貨率須肉眼可區分（75% / 85% / 95%），不得再出現三檔同值。
- 驗收：① 三檔到貨率海運 < 聯運 < 空運；② REQ-049 矩陣重跑：正常線仍全贏（因最便宜檔下限不變，新手友好底線未動）；③ 拉爆線（×1.8、×0.7 深折 + 付費流量）仍全虧；④ W5 展示值與結算實際到貨率一致。

**REQ-056 選市場場景化 + 容量條可見** `M` ❌新增

- 機制：① 地圖原生選市場：點地圖上的市場研究樓直接選市場，不再彈舊面板；② 市場卡上顯示容量條（預計到訪 / 容量），超量提示「再多流量也只能算一半」；③ 平台三家在第一步用一句話差異卡並排呈現：TikTok（6% 佣金、零入駐）、Amazon（15% + 每輪 $39、轉化 ×1.12）、獨立站（$500 一次、流量 ×0.75）；④ 選品頁顯示匹配度檔位（高 / 中 / 低，由真實 fit 映射，不給精確數字）；無 fit 數據的商品顯示「匹配度待測」+ 首測免費提示，**不給星**（未知不得顯示為中等）。
- 驗收：stage 0 全程無舊面板；容量條在市場卡上可見且超量有提示；平台三選一能說出各自代價；無數據商品無星星顯示。

**REQ-057 結算現金時間線事前預警** `S` ❌新增
- 背景：銷售款下輪開局才到賬，結算頁「現金變化」會是一個大負數；徹底修法（定價步即提示缺口、結算不再硬擋）是否已落地未證實（P1 附錄 A 說「留在 P1」，附錄 B 未列出）。
- 核查口徑（先核查、後動手）：實現方開工前先以實機截圖證明「定價步已提示結算現金缺口且結算不再硬擋」；能證明則關閉本項（附截圖編號），不能證明則按正文做，不得以「應該做了」帶過。
- 機制（未落地時做）：① 定價步即提示「本輪成本約 $X，收入下輪到賬，結算時需現金 $Y」；② 推廣步同步更新缺口；③ 缺口 >0 時主按鈕置灰 + 寫明差多少；④ 過橋貸選項前置到缺口提示裏，不再結算時才出現；⑤ 結算不再出現「交付前現金不足」硬擋。
- 驗收：構造現金不足方案，定價步即見預警且寫明差額；結算不再硬擋；過橋貸選項在缺口提示中可見。
