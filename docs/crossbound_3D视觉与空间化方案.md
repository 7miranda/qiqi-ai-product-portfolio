# Crossbound 3D 视觉与空间化方案（2026-10-25，调研稿，待用户定方向后交 Codex）

## 1. 你要的意思，我理解成这样（先对齐，再动手）

- **现状问题**：现在界面是平面表单式——点卡片、填数字、看表格，像个后台，不像在"玩游戏"。
- **目标感觉**：视频里那种"一个活的房间"——深色霓虹的办公室，工位上有小人在走动，墙上挂着 K 线和数据屏，数字和连线在空中飘，底部还有一条余额曲线在实时爬。**先说一个关键判断：视频里这个其实不是真 3D，而是 2.5D 等距视角 + 动态数据层。** 这是好消息：用 Web 技术就能做出来，成本远低于真 3D 渲染，也更适合现有纯前端栈。
- **空间化玩法**：不再是"一页表单做完一关"，而是**一个环节 = 一个空间**——玩家像真的在游戏里一样，从一个房间走到下一个房间、做完事才通关。Steam 上教育/模拟类游戏（Two Point Hospital、Game Dev Tycoon 那一挂）就是这个路子：空间即进度，房间即关卡。

## 2. 视频里值得偷的元素（拆解）

| 元素 | 在视频里的样子 | 搬到 Crossbound 的方式 |
|---|---|---|
| 等距房间 | 一间俯视 45° 的办公室，工位、绿植、火箭摆件 | 总部大楼一层：工位 = 你的团队，随等级变多 |
| 房间里的小人 | 彩色小圆点角色在工位间走动、聚团 | 选品/推广/履约时有小人"干活"：打包、直播、搬箱子 |
| 墙面数据屏 | K 线、网络节点连线、指标卡 | 墙面 = 战报可视化：利润曲线、订单流、风险灯 |
| 顶部指标条 | CHIEF / SCAN / VET / SOCIAL / SIZE / FILLS / RISK / CRAWLER | 顶部 = 本轮关键指标：现金、库存、订单、回款、风险 |
| 底部曲线 | 余额随时间爬升的曲线图 | 底部 = 本轮现金/利润曲线，结算时定格成战报 |
| 霓虹描边 + 深底 | 粉色描边、暗色底、荧光数据色 | 主视觉方向：深底霓虹数据风（备选见 §4） |

## 3. 空间化结构：七环节 → 七个房间

总部大楼是常驻 Hub；每轮玩家按顺序"走"过房间，上一间做完，下一间才点亮。

| 顺序 | 房间 | 对应现有环节 | 房间里能看到/能点的东西 | 解锁条件 |
|---|---|---|---|---|
| 0 | 总部大厅（Hub） | 选市场、看总览 | 世界地图墙（12 国节点，参考视频的节点连线）、排行榜/成就墙 | 常驻 |
| 1 | 选品展厅 | 选商品、选供应商 | 货架上的商品 3D 模型、供应商来"送样"的小人 | 第 1 轮默认开 |
| 2 | 定价财务室 | 定价、备货量 | 大算盘/价格牌、库存货箱随备货量变多变少 | 完成选品 |
| 3 | 商品页工作室 | 上架、标题主图风格 | 一面"商品页"大屏，分数随选择实时涨跌 | 完成定价 |
| 4 | 直播间 / 推广室 | 选推广渠道 + 二级决策 | 内容号：主播小人开播；广告：投流大屏；达人：达人小人入场 | 完成上架 |
| 5 | 物流仓 | 选履约、头程 | 叉车、货箱、飞机/货轮小动画；海运慢、空运快看得见 | 完成推广 |
| 6 | 财报结算厅 | 结算、看三大表 | 利润瀑布变成墙面图表；现金流断了房间灯变红（教学点可视化） | 完成履约 |
| 7 | 荣誉墙 / 成就馆 | 成就、共建者徽章 | 已获得的徽章挂墙上（REQ-040 的实体化） | 常驻，随获得点亮 |

**通关逻辑（不改引擎，只改表现层）**：现有 stage 顺序不变，每个 stage 对应一个房间；房间状态 = 未解锁（灰色上锁）/ 当前（高亮、门开着）/ 已完成（亮灯）。跨轮成长：大楼随等级 LV.1→LV.10 变化——工位变多、楼层变高、装饰变丰富，等于把"成长线"画出来。

**第 1 轮 vs 第 2 轮**：第 1 轮只开 0–3 号房的简化版（与 v1.1 简化引擎一致）；第 2 轮起开放平台选择（直播间分 TikTok / Amazon / 独立站三间小隔间）、头程（物流仓多一条航线）、事件（随机事件小人闯进来报信）——与 REQ-050 的"渐退教学"同节奏：新房间出现时才教。

## 4. 视觉语言

- **主方向（推荐）**：深底霓虹数据风——贴视频参考，数据感强、"真的在经营"的味道最浓；且深色底在手机上省电、数字对比度高。
- **备选**：明亮卡通风（toony 低多边形）。优点是更亲和、更像 Steam 休闲模拟；缺点是与视频参考差得远、数据感弱。**二选一，用户拍板。**
- **不动的东西**：数值、引擎、规则全部不动；只换表现层。现有 v2/core.js、v11/model.js 继续算账，3D 层只负责"把算出来的东西演出来"。

## 6. 技术路线（给 solo + 现有栈的建议）

- **路线 A（推荐）**：three.js + 低多边形资产。CDN import map 引入，与现有 ES module 结构兼容，**不需要构建步骤**（与 business-tycoon 同款路线）。表现层独立成 `v3/view-3d/`，引擎（core/model）一行业务代码不动，只把算好的 state 喂给 3D 层渲染。
- **路线 B（最便宜）**：2.5D Canvas 等距手绘。零依赖、性能最好、最贴近视频原生的做法；缺点是表现力上限低、后期想转真 3D 要重写。
- **路线 C（将来上 Steam 再考虑）**：Godot 导出 HTML5。优点是真能上 Steam、编辑器成熟；缺点是等于重写前端，现阶段不划算。**先 A，Steam 是后话。**
- **落地顺序**：P0 总部大厅静态等距场景 + 顶部指标条 + 底部曲线（先验证"感觉对了"）；P1 七个房间切换 + 上锁/点亮状态；P2 小人走动、货箱、航线动画；P3 跨轮大楼成长。
- **性能红线**：移动端优先——模型面数低（单件 <500 面）、阴影烘焙不实时算、粒子和连线动画做数量上限；低端机自动降画质（参考 §5D 文章）。
