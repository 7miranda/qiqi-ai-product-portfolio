# Crossbound 埋点需求：游戏即面试（v1.1 配套，单独文档）

> 编写日期：2026-10-19
> 输入：复盘文档第八节第 4 条"游戏不只是漏斗，还是'面试'" + 第 9 条（否决双身份开场，行为自动分流）
> 定位：**单独文档，不进 PRD 正文**（PRD 按要求先不动）；开发可直接按事件表实施；运营按标签规则跟进

## 1. 为什么要做（给开发 / 运营一句话）

游戏 = 获客漏斗 + 合作筛选器。埋点的终极输出不是"玩家玩得好不好"，而是 **"这个人值不值得运营跟进、跟进时说什么"**。

北极星链路：达人进来 → 玩懂 → 留资 → 真实合作。埋点是"玩懂→留资"之间那只看不见的手。

## 2. 设计原则（评审时回看）

1. **按评估维度设计，不按游戏数据设计**：先定"要评估什么人"，再定"埋什么事件"。
2. **一套埋点，两套评估口径**：达人 / 有一点跨境经验的人，同一批事件，两种打分口径。
3. **筛选是后台静默的**：玩家侧永远只看到"爽"，看不到"考试"（配合 REQ-023 前 3 轮游戏向、难度逻辑反转：获客工具先爽后筛）。
4. **最小可用**：v1 只埋 12 个核心事件（标 ★），决策快照存原始 JSON——口径以后随便改，不用返工埋点。

## 3. 评估维度 × 可观测行为矩阵

### 3.1 达人口径：内容 sense / 选品眼光 / 风险偏好 / 学习速度

| 维度 | 可观测行为 | 映射关卡 / 功能 |
|---|---|---|
| 选品眼光 | 选的品类档次、是否碰高复杂度高毛利品类；人设×选品匹配度（洞察 #2，若已上线） | 选品关（product）、上架关（REQ-006 上架分） |
| 内容 sense | 是否使用"内容制作三选一"（选题/钩子/封面，洞察 #2）；达人渠道选择频次与预算占比 | 推广关（traffic，达人渠道） |
| 风险偏好 | 定价偏离建议价的幅度（敢不敢加价）；预算滑块位置（300–8000 区间内的激进程度）；是否 all-in 单渠道 | 定价、推广关 |
| 学习速度 | 第几轮**首次**打开归因页（REQ-007）；总部来电 quiz 答对率的变化趋势；是否复看"？"逻辑卡 | 归因页、总部来电（HQ-call） |

### 3.2 有经验者口径：运营精细度

| 维度 | 可观测行为 | 映射关卡 / 功能 |
|---|---|---|
| 成本意识 | 是否展开结算页退款拆解（REQ-002 三类）、停留时长；是否查看"退货损失"行 | 结算页 |
| 结构优化 | 渠道组合是否分散（是否仍走"150% 顶格价 + 广告 + 加急"无脑最优解）；是否使用清仓按钮（REQ-013） | 推广关、库存关 |
| 节奏感 | 备货与上架是否并行推进；扩张关（expansion）进入时机的选择 | 备货关（stock）、扩张关 |

### 3.3 受众自动分流规则（代替双身份开场的关键机制）

> 洞察 #9：不开双身份开场，漏斗入口零摩擦。**谁是谁，由行为说了算。**

- **达人-leaning 信号**：首轮选达人渠道 / 使用内容制作三选一 / 人设×选品匹配度持续偏高
- **运营-leaning 信号**：首轮选广告渠道 / 频繁查看归因页与结算拆解 / 多渠道组合投放
- **混合型**：两侧信号都强 → 按更强的一套口径打主分，另一套做参考分（运营跟进时两手都有话说）
- 分流结果**只写后台标签，不告诉玩家**（避免"你被分类了"的不适感）

## 4. 事件表（v1 最小集 ★ = 必埋）

| # | 事件名 | 触发时机 | 关键字段 | 服务维度 |
|---|---|---|---|---|
| ★1 | `game_start` | 进入游戏 | 来源（分享卡 / 自然）、设备、版本号 | 漏斗入口 |
| ★2 | `level_decision` | 每关提交决策 | 关卡名、轮次、决策快照 JSON、决策用时 | 全部 |
| ★3 | `pricing_set` | 定价确认 | 售价、建议价、偏离率 | 风险偏好 |
| ★4 | `channel_pick` | 推广渠道选择 | 渠道（广告 / 达人 / 内容）、各渠道预算 | 内容 sense / 结构优化 |
| ★5 | `listing_submit` | 上架提交（REQ-006） | 上架分、标题/主图选项 ID | 选品眼光 |
| ★6 | `attribution_view` | 打开归因页 | 轮次、停留时长、是否首次打开 | 学习速度 |
| ★7 | `hq_quiz_answer` | 总部来电答题 | 题目 ID、对错、答题用时 | 学习速度 |
| ★8 | `settlement_view` | 结算页展示 | 轮次、退款拆解是否展开、停留时长 | 成本意识 |
| ★9 | `round_complete` | 每轮结束 | 轮次、订单数、利润、目标达成（首轮 300 / 后续 500） | 全部 |
| ★10 | `share_card` | 战绩分享卡生成 / 分享 | 分数、分享渠道 | 漏斗回流 |
| ★11 | `lead_submit` | 留资提交 | 表单字段（见 §6）、来源轮次 | 漏斗转化 |
| ★12 | `funnel_stage` | 运营侧标记 | 进入 / 玩懂 / 留资 / 已建联 / 已合作 | 漏斗归因 |

非 ★ 的 v2 再补：`content_create`（内容三选一明细）、`persona_match`（人设×选品匹配分）、`story_view`（"小雅的故事"类内容阅读）。

## 5. 派生指标与标签规则（示例阈值，运营可调）

- **高意向（自动打标）**：完成 ≥3 轮 AND（达人口径任一维度 ≥P75 分位 OR 运营口径综合分 ≥P75）→ 进入运营跟进池。跟进话术模板："你在游戏里第 X 轮选的 XX 品类，我们正好有真实货源在招达人，要不要看看？"
- **教学对象**：HQ quiz 连错 ≥3 次 / 从未打开归因页 → 推送"隔壁达人小雅的故事"类内容（洞察 #8），不推"？"干货卡。
- **流失预警**：首轮未完成 → 下次进入时提示简化（配合难度反转：先让她爽）。
- **出海 readiness 评估**（记忆中待新增 REQ 的候选）：综合分 → 一句话评价，显示在战绩分享卡上（"你的选品眼光超过 82% 的玩家"）。

## 6. 留资闭环（最小字段，别贪）

- **战绩分享卡**（待新增 REQ 候选）：分数 + readiness 一句话评价 + 分享回流埋点（`share_card`）。
- **留资表单**：联系方式（微信 / 手机二选一）+ 达人类目 + 粉丝量级（达人-leaning 显示）/ 主营类目（运营-leaning 显示）——按 §3.3 分流结果动态切换，只问 3 个字段。

## 7. 实施备注（给开发）

1. 前端事件直发即可，无需后端实时计算；标签与分位 offline / 定时任务跑。
2. `level_decision` 的决策快照存**原始选项 JSON**，不要只存算好的分——评估口径以后调整不返工。
3. 留资提交前不收集任何可识别信息；隐私文案一句话即可（"数据仅用于为你匹配合作机会"）。
4. 工作量：`S`（事件表 12 个，均为前端埋点 + 后台标签定时任务）。

| REQ | 在本埋点体系中的角色 |

| REQ-007 归因页 | 是否打开 / 第几轮打开 / 停留 = "学习速度"主观测点 |
