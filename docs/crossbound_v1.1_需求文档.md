## 1. 版本目标

**一句话**：把"算术游戏"升级为"经营游戏"，服务三类用户——**新手（学）、泛经营玩家（爽）、达人（走向真实合作）**。

**游戏定位**：获客漏斗 + 教育工具 + 合作筛选器。游戏内留存/付费不是目的；目的是让人进来、玩懂、愿意真实合作。

**北极星**：**达人进来 → 玩懂 → 留资 → 真实合作**。当游戏内指标与漏斗指标冲突时，以漏斗为准。

**四个可衡量的目标**（按优先级）：
1. **爽感先行**——作为获客工具，第一性是"爽 + 我能行"：新手 3 轮内玩爽、达人第 1 轮就有"我能带货"的感觉；上难度的改动缓行；
2. **玩懂有路径**——教育分层：达人看故事（总部来电/跟卖剧情），新手看逻辑卡（"？"下钻），泛经营玩家看数字和战报；决策→反馈延迟缩短（归因、驾驶舱）；
3. **合作有出口**——筛选器落地：认证体系（REQ-034）+ 认证卡留资 + 行为数据评估（"游戏即面试"）；
4. **不再教错**——P0 真实性修复（退款/关税/时效）作为"玩懂"的地基，但只修不教错的地方，不叠加难度。

**非目标**（v2 再说）：不加硬门禁、不做双模式、不做完整经济系统（账期/仓储/破产事件/大卖季节点）、不开双身份开场（漏斗入口零摩擦，见 §2）。

## 2. 设计原则（本版本宪法，评审时回看）

1. **牵引代替管制**：初版不加限制。别做"墙"，做"灯"——门全开，灯光打在推荐的路上。
2. **三受众分层**：新手（学）+ 泛经营玩家（爽）+ 达人（走向真实合作）。**游戏为表，模拟器为里，漏斗为底**；教育分层——达人看故事、新手看逻辑卡、泛玩家看数字战报；透明但不强制（"？"下钻）。
3. **先爽后学（获客逻辑）**：前 3 轮游戏向（爽、快），之后引入教学向（归因页讲"为什么"）。难度逻辑反转：作为获客工具，上难度的改动缓行，优先保证"爽 + 我能行"。
4. **交集先行**：三受众共同受益的先做（真实性修复 > 纯爽点 > 纯教学点）；达人专属（认证/合作引导）单独排期，不拖累主线。
5. **北极星优先**：评审时遇到"游戏内指标 vs 漏斗指标"分歧，一律以漏斗为准（进来→玩懂→留资→真实合作）。
6. **漏斗入口零摩擦**：不开双身份开场；用成长线代替身份分支——单主角"出海合伙人"，达人能力/运营能力都做成可成长技能树，玩家按短板自选补齐，行为数据自动分流评估。

**REQ-001 退款改沉没成本模型** `M`

**REQ-048 财报 · 三大表** `M`（2026-10-21 新增，源：傲基测试反馈"玩法上还是要有财报、三大表"）
- 背景：v2 引擎已有现金/库存/应收/应付/桥贷/14 天回款全套资金数据，但只散落在战报明细行里，玩家看不到"经营全貌"。三大表是跨境经营的常识课，也呼应"真实模拟"定位——本 REQ 以**呈现层为主，不新增数值系统**。
- 入口：结算区新增「财报」页签（与战报/评估并列）；每轮结算自动生成本期财报，历史轮次可翻看。
- **利润表**：收入 → 退款 → 各项成本（货品/退货处理/上架/运费/平台费/佣金/推广/关税/进口税/收款费/换汇/头程/仓储/利息）→ 毛利 → 净利润；复用战报瀑布数据并补汇总行，口径与战报严格一致。
- **资产负债表**（期末时点）：资产 = 现金 + 存货（余货 × 单位成本）+ 应收账款（待到账）；负债 = 应付采购款 + 桥贷未还本金；净资产 = 资产 − 负债；每行带与上轮对比的变化箭头。
- **现金流量表**：期初现金 + 本轮到账回款（含上轮应收在本轮到账部分）− 本轮实际付现（采购/运费/税费/推广/利息等）= 期末现金。
- **勾稽自检（硬验收）**：①资产 = 负债 + 净资产；②本轮净资产变动 = 本轮净利润；③期末现金三处一致（现金流量表结果 = 资产负债表现金行 = 实际现金）。任一对不上即 bug，不许上线。
- 教学化（守 REQ-032 口径）：科目用标准名 + 小字人话注释（如应收账款旁注"货卖了、钱还没到账的部分"）；每表底部一句话解读；**重点讲清"利润 ≠ 现金"**：差额来源逐项点名（未到账 $X + 压在货上 $Y）——这是跨境经营第一课。
- 预警：期末现金 < 近期应付时，资产负债表红字提示"现金可能接不上应付"（接 REQ-019 触发式提示）。
- 兼容：v1.1 轮次无账期数据，只出利润表；v2 轮次出全三表。与 REQ-046 联动：完整版评估报告引用净资产变化（$50,000 → $X）作成绩锚点。
- 验收：任意 v2 轮次结算后三表生成且勾稽三条全过；玩家能从财报一句话答出"本轮赚了多少、现金剩多少、钱压在哪"。

## 7. 风险与对策

1. **REQ-001 会显著提高难度** → ~~同步重调退款率数值 + 新手前 2 轮补贴~~ **【2026-10-20 用户决策：不做难度补贴】**——不加任何补贴机制，保持简单、让用户觉得通关很容易优先。数值锚点改为"易通关"：退款参数向宽松侧校准（与回库率接受现行 50%/20% 的决定一致）。
2. **首个随机数 vs 回滚"公平比较"** → 方案：随机种子按"轮次"固定（同轮回滚结果一致，跨轮有差异），回滚文案同步更新，避免"开卷考试"回潮。
3. **REQ-006 新增一关** → 六关变七关，底部进度条与教学文案同步更新；存档结构加 `listingScore` 字段（老存档默认 80 分兼容）。
4. **工作量风险**：27 个 v1 REQ 对单人团队偏多 → 建议分两批：第一批 P0 + 揭示设计（REQ-001~005、015~021、024~025），第二批 P1（REQ-006~014、022~023、032、037）。每批独立可玩、可验收。
5. **v1 最小改动集**（只动 5 处，投入产出比最高）：REQ-001 退款沉没成本 + REQ-008 涨价惩罚 + REQ-011 预览区间化 + REQ-006 上架一关 + REQ-007 归因页。改完效果："教错"的摘掉（退款），"无脑解"破掉（涨价惩罚+预览区间），"学不到东西"补上（上架+归因）——初版就能立住。
